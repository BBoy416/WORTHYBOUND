# ADR 0013: Automated checks and guided capture

- Status: Proposed
- Date: 2026-09-29

## Context

Anyone can upload anything, so uploads alone prove little (ADR 0003 caps self-documented assets at
35). Professional verification (ADR 0012) raises trust, but appraisers are scarce and cost money,
and most assets would stay at the self-documented level. Photos taken earlier, found online or
generated by AI, and edited receipts, are the cheapest ways to fake a passport. Automated checks
can catch much of this cheaply, but cannot handle the item, can be probed until they pass, and
produce results that are hard to reproduce.

## Decision

**Automated checks support professional verification; they never replace it.** They give assets
a meaningful score without an appraiser, flag fakes, and prepare material so an appraisal is
faster. The upper part of the scale still needs professional verification.

**Guided capture.** Photos that count as captured on the spot come from a capture session:

1. The owner starts a session for an asset. The server records it and returns a one-time code
   (valid 15 minutes) and the shots required for the category, e.g. for a watch: dial, caseback,
   clasp, serial, side, and one photo of the item next to the code written on paper; optionally a
   short video turning the item.
2. The shots are taken with the camera in the app or browser during the session, not picked from
   the gallery, and uploaded through the Evidence Vault pipeline (ADR 0010): server-side hash,
   type detection, immutability, seal.
3. The session is complete when every required shot arrived before it expired. The server records
   when each shot arrived and its SHA-256. File metadata (EXIF dates, GPS) is never trusted.

Capture sessions are reused for possession and condition confirmation and for the checks before
and after a sale (ADR 0014).

**Checks.**

| Check                    | What it looks for                                                                                     |
| ------------------------ | ----------------------------------------------------------------------------------------------------- |
| Capture                  | All required shots present, code visible and correct, taken within the session                        |
| Same item                | All shots show one item, matching the claimed brand and model                                         |
| Re-photographed or fake  | Photos of a screen or print, AI-generated or edited images                                            |
| Reuse                    | The same or a near-identical photo elsewhere: on other assets or online (exact copies: ADR 0010)      |
| Document consistency     | Receipt, certificate or service record text matches the asset: brand, model, serial, a plausible date |
| Document forgery signals | PDF edit history and producer, inconsistent fonts or layout, totals that do not add up                |
| Document reuse           | The same receipt or receipt number on another asset                                                   |

Deterministic checks (capture, reuse by perceptual hash, PDF metadata, document text matching)
are built first, in the API and worker. Image forensics and model matching use a third-party
service, chosen later behind an interface in a new package, so it can be replaced.

**Results are records, not opinions.** Each check result stores the check, the result (`PASSED`,
`FAILED`, `INCONCLUSIVE`), findings, the engine or model and its version, the time, and the SHA-256
of every file it examined. Results are append-only. A result is never changed; a newer check
supersedes it. This keeps every score reproducible (ADR 0003).

**Trust Score (Phase 9).** A new proof source `AUTOMATED` with its own weight and ceiling:

| Level                                           | Score cap                                 |
| ----------------------------------------------- | ----------------------------------------- |
| Self-documented                                 | 35 (45 with KYC, unchanged)               |
| Passed automated checks (guided capture passed) | 55                                        |
| Professional inspection                         | above 55 (existing tiers of ADR 0003)     |
| Two independent professionals                   | above 90 for high-risk categories (as is) |

Failed checks deduct: a forged document or reused photo lowers the score and blocks template
evaluation until a verifier reviews it. An automated check never sets `VERIFIED` and never
confirms a claim on its own; it is evidence of a stronger kind than owner uploads.

**What owners are told.** Owners see whether a check passed, failed or was inconclusive, with the
category of problem (e.g. "the code was not visible", "this photo appears elsewhere"), not the
detection details. Details go to the audit log for admins. Capture sessions are limited per asset
and per user per day, so the checks cannot be probed cheaply.

**Identity.** KYC stays with a third-party provider (ADR 0004); providers check a live selfie
against the identity document on the spot. WorthyBound still stores only status and reference.
Reusable or zero-knowledge identity proofs can replace this later without changing the rest.

**Privacy.** Private evidence is sent to a third-party service only with the owner's consent,
given per asset before the first check, under a data processing agreement that forbids training
on it and limits retention. Deterministic checks run on WorthyBound's own infrastructure. Check
results are private; the passport shows only that automated checks passed, and when.

## Consequences

- Most assets can reach a meaningful score without an appraiser; appraisers are needed for high
  values and the top of the scale.
- Automated checks can be wrong in both directions. The passport always states what was checked
  automatically and keeps the Trust Score disclaimer.
- An identical super-fake can pass photo checks; only professional inspection, or physical tags
  (ADR 0014), addresses it.
- Guided capture needs a camera-capable client (web or mobile), which does not exist yet.
- A third-party service adds cost per check, which the business model has to cover.
- Adds a proof source and weights: a new weights version and engine version (ADR 0003).
